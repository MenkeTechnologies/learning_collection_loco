>_OVERVIEW

A line-for-line Rust rewrite of the Kotlin/Spring Boot LearningCollectionAPI: a tiny CRUD service over a single LearningCollection entity with add / filter / recents / random / dump verbs. Spring's @RepositoryRestResource(path="learning") auto-CRUD is replicated as explicit Axum handlers; CrudRepository-style findAllByLearningContaining becomes a SeaORM Column::Learning.like("%pat%") filter; WebConfig CORS lives in config/development.yaml; Flyway / ddl-auto is replaced by sea-orm-migration. Same routes, same shapes, native binary.

[0x00] Quickstart

git clone https://github.com/MenkeTechnologies/learning_collection_loco
cd learning_collection_loco

cargo loco db migrate
cargo loco start          # http://localhost:5150
cargo loco routes         # list every registered route

SQLite is the default for zero-setup dev. Swap to MySQL/Postgres by editing database.uri in config/development.yaml and toggling the SeaORM driver feature in Cargo.toml (sqlx-sqlite → sqlx-mysql / sqlx-postgres).

[0x02] Spring → Loco Mapping

Entity

@Entity LearningCollection → models/_entities/learning_collections.rs, SeaORM DeriveEntityModel. id, learning, category, date_added — same shape; SeaORM adds created_at / updated_at automatically.

Repository

LCRepo : CrudRepository<LearningCollection,Long> with @RepositoryRestResource(path="learning") → explicit Axum handlers under /learning. findAllByLearningContaining(s) → Column::Learning.like("%s%") inside filter_learn.

Controller

LearningController.kt → src/controllers/learning.rs. Every verb preserved (add, filter, recents, recent, random, randoms, dump). Path params and query params decoded by Axum extractors instead of @PathVariable / @RequestParam.

CORS

WebConfig CORS → config/development.yaml → middlewares.cors. Zero hand-written middleware code — flip the YAML block to whitelist origins.

Datasource

application.properties MySQL DSN → config/{development,test,production}.yaml → database.uri (SQLite by default). Swap by editing the URI plus the sea-orm feature list in Cargo.toml.

Migrations

Flyway / spring.jpa.hibernate.ddl-auto → sea-orm-migration under migration/ + auto_migrate: true in YAML. One migration: m20260601_044042_learning_collections creates the table with id PkAuto / learning / category / date_added.

Bootstrap

SpringApplication.run → cargo loco start. src/app.rs implements Hooks; create_app::<Self, Migrator> wires migrations, controllers, workers, tasks. AppRoutes::with_default_routes mounts the framework's health endpoints.

Constants

Consts.kt → pub consts at the top of controllers/learning.rs: SHORT_CNT, DEFAULT_CAT, DB_NAME, dump_cmd(). Same names, same values.

What disappears

No Lombok, no QueryDSL, no springdoc-openapi, no Hibernate session, no JVM warmup. SeaORM types replace QueryDSL; utoipa covers OpenAPI if needed. JIT, GC pauses, and 2-second startup banished.

[0x05] Intentional Drift From the Original

  • DB — SQLite for zero-setup dev. The Spring app talked to MySQL (root). Driver swap is a YAML + Cargo.toml feature toggle.
  • /dump — still shells out to mysqldump. Behaviorally identical, but only meaningful when pointed at MySQL. For SQLite: sqlite3 db .dump.
  • @RepositoryRestResource — Spring auto-generates HAL pagination, _links, PATCH/POST/PUT for free. The port exposes GET-list / GET-one / DELETE explicitly. Add POST/PUT via cargo loco generate scaffold when needed.
  • Tooling parity — Lombok → derive. QueryDSL → SeaORM type-safe query API. springdoc-openapi → utoipa (opt-in).
  • Timestamps — SeaORM adds created_at / updated_at for free; date_added kept as in the original.
